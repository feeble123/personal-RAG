## Key Questions
1. 当前系统从上传到回答的真实端到端数据流是什么，在哪些节点损失信息？
2. 两种切片策略分别优化了什么，是否有可测量收益，LLM 切片是否引入成本、漂移或结构破坏？
3. 索引与检索实现能否在规模、并发、增量更新、多租户和失败恢复场景下工作？
4. 当前“多数答案精准”的判断是否有评测集、指标和可复现证据支撑？
5. 上线前哪些问题属于阻断项，哪些属于后续增强？

## Decisions Made
| Decision | Rationale |
|----------|-----------|
| 仅做审计、测试和报告，不修改业务源码 | 用户当前要求评估而非实施修复；避免改变待审对象 |
| 把现有未提交修改视为用户资产 | 工作树在审计开始前已存在修改，必须完整保留 |
| 结论区分静态证据、测试证据与推断 | 避免把未运行的路径描述为已验证事实 |

## Errors Encountered
| Error | Attempt | Resolution |
|-------|---------|------------|
| Git 无法读取用户级 ignore，出现 Permission denied 警告 | 1 | 不影响仓库状态读取；后续使用显式文件枚举并记录该环境限制 |
| 当前 PowerShell/.NET 不支持 `[System.IO.Path]::GetRelativePath`，递归枚举产生大量错误且输出截断 | 1 | 改用 `Resolve-Path -Relative`/`rg --files`，并显式排除依赖缓存、构建产物和虚拟环境 |

- 计划与发现文件仅用于本次审计，不改动业务实现。
