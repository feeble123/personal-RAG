# 单元 N：口语→术语 规则映射表（查询扩展）

> 背景：单元 M 收紧评测后，模糊题严格 Recall@5 = 77.8%（A 100% / B 50% / C 66.7%）。
> 三个失败点根因已定位（诊断脚本 `evaluation/recall_rootcause.py`）：
>
> | # | 题 | 根因 |
> |---|---|---|
> | 1 | 农村供水要建哪些东西 | 向量把「要建哪些东西」连不到「系统组成」（0.270），正确块排第9 |
> | 2 | 土石下滑怎么看稳不稳 | 向量已召回正确块（0.697），但 rerank 因聚焦词缺失给 0.003 全灭 |
> | 3 | 什么时候按长管算 | 定义块在库（section 噪声+内容切散），向量+BM25 都没召进候选池 |
>
> 共同引子：`focus_rerank_query` 不认「怎么看/要建哪些/什么时候…算」问法。但病根分两层——
> 召回层（#1/#3）与 rerank 层（#2）。用户拍板：**用「口语→术语」规则映射表补这层映射**。

## 一、方案：查询扩展（append 不 replace）

新增 `backend/app/services/query_expand.py`，提供 `expand_query(query) -> str`：

- 维护一张**口语/宽泛表达 → 规范术语**映射表；
- 命中时把**规范术语追加**到原查询末尾（**不删除原文**）——加词是「给信号」，删词是「丢信息」，
  万一映射错了，最多多一个无关词，不会把原来能命中的问法搞丢（低回归风险）；
- 只在 `retrieve()` 入口生效，作用于向量 / BM25 / rerank 三层的查询；
  **不影响**语义缓存、记忆库、用户可见提问（那些仍用原始问题，缓存键不变）。

## 二、初始映射表（保守，覆盖已知失败 + 明显水利口语）

| 口语表达（触发） | 追加术语 | 为什么 |
|---|---|---|
| `稳不稳` / `稳不稳定` / `稳吗` | `稳定性` | #2：救「土石下滑稳不稳」 |
| `建哪些` / `要建哪些` / `有哪些东西` | `系统组成` | #1：救「要建哪些东西」 |
| `按长管算` / `长管计算` | `长管计算依据` | #3：救「按长管算」 |
| `垮了`（且句含`坝`/`堤`/`堰`/`库`） | `溃坝` | 口语「垮了」→「溃坝」（带上下文守卫，防「桥垮了」误加） |
| `平稳还是乱` / `水流平稳` | `层流 紊流` | 口语「平稳还是乱」→流态术语 |

设计原则：
- 触发词取**多字短语**（不用单字），降低误伤；
- 歧义词（`垮了`）加**上下文守卫**（同句含坝/堤/堰/库才加「溃坝」）；
- 命中即追加、不命中原样返回；映射表是**可增长**的（以后发现新口语词，加一行即可）。

## 三、改动清单

1. **新增 `backend/app/services/query_expand.py`**：`expand_query()` + 映射表 + 上下文守卫。
2. **改 `backend/app/services/rag.py`**：`retrieve()` 入口把 `query` 扩成 `rq = expand_query(query)`，
   下游 `embed_query(rq)` / `bm25.search(..., rq, ...)` / `focus_rerank_query(rq)` 用扩展后的查询。
3. **新增 `backend/tests/unit/test_query_expand.py`**：
   - 正例：`稳不稳→稳定性`、`要建哪些→系统组成`、`按长管算→长管计算依据`、`大坝垮了→溃坝`
   - 反例（不误伤）：`桥垮了` 不加溃坝、`什么是雷诺数` 原样返回、`垮` 单独出现不追加
4. **重跑模糊评测** `run_vague_eval`，看严格 Recall@5 变化（目标 77.8% → ≥90%）。

## 四、验收标准（数字说话）

- 模糊评测严格 Recall@5 从 **77.8%** 提升（预期 #1/#2 修复后 → 88.9%+，即 8/9；#3 视扩展效果）
- 60 问正式评测（`run_eval`）**不回归**（Recall@5 98.3% 保持）
- pytest 全量绿
- 三个失败点单独复测：正确章节进 top5

## 五、风险与边界

- **低风险**：只加词不删词；只在检索查询生效，缓存/展示不受影响；映射表保守、可回滚。
- **#3 可能不完全解决**：定义块 section 是噪声（`5有压管道流动`/`4.则`）且内容拦腰切散，
  扩展能帮 BM25 把「长管计算」捞出来，但若仍不够，说明是**切片质量问题**，另开单元修（记档）。

## 六、不改的部分

- 不动 `focus_rerank_query` 的问法识别（那是另一条路，本次不碰）
- 不动向量/BM25/RRF/rerank 算法本身
- 不动语义缓存、记忆库、用户可见提问
- 不 push 远程
