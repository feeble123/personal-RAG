## 二、重新组合成 6 个新单元

按「主题内聚 + 依赖关系」重新打包。每个新单元是一个**主题块**，执行时再拆成小步骤（步骤间仍停等验收）。

### 单元 O：评测尺子校准（小 · 低风险 · 建议先做）

**为什么先做**：后续所有优化（召回、解析、存储）都要靠评测数字来证明「变好了」。尺子不准，后面都是白忙。先校准尺子，花小力气铺路。

**内容**：
1. gold 集 2 题标注修正：滑坡勘察题换到正确库、建设目标题换成原文真实问法（需您确认后再改 `gold_data.py`）
2. 核对 60 问 `expect_clauses` 锚点是否齐全，缺的补上

**验收**：gold 集本身可信（每题的答案块在库里真实存在）；跑一遍 `run_eval` 得到可复现基线数字。

---

### 单元 P：召回完整性（检索质量主线收尾）

**为什么**：现在 Recall@5 98.3%，剩的最后一块短板是「找得到但不全」——预警信息题、集合题这类「要全部/要清单」的问法。

**内容**：
1. 预警信息题召回增强：诊断为什么「3.4 预警分级」答案块没进候选池，修召回层策略（向量/BM25/候选池）
2. 集合题「完整列举」：核实当前「全部/清单/名单/有哪些」是否走完整列举还是靠 top-k 猜，有缺口就补 exhaustive 路径

**验收**：预警信息题正确章节进 top5；集合题 row recall 到多少（先测基线再定目标）；60 问 Recall@5 不回归。

---

### 单元 Q：解析完整性（文档读得准）

**为什么**：扫描规范还有横置页没转正、复杂表格/Excel 还读不准、图片内容搜不到。这块直接决定「答案对不对」。

**内容**：
1. P1-3 旋转页自动纠正（横置表格转正，不再切成条）
2. P1-4 复杂表格 + Excel 结构化查询（多行表头、合并单元格、日期列不串行；「全部/按日期筛选」走结构化查询而非向量猜列）
3. 图片检索进阶版：图片存盘 + 视觉模型读图，把图里的标注/数字变成可检索文字

**验收**：旋转页纠正率 100%（评测集内）；表格关键字段映射 ≥98%；图片块能搜到图内文字；无回归。

> 注：单元 Q 的第 1、2 项，最终用哪个引擎，可能受单元 S（bake-off）结论影响——详见「依赖关系」。

---

### 单元 R：存储地基（pgvector 迁移）

**为什么**：现在向量存在 Chroma（嵌入式文件），和数据库（PG）是两套东西，双写、双备份、容易漂移。迁到 PG 内置向量后，权限、版本、向量、审计在一张事务里，更稳、更可维护。

**内容**：
1. 建 PG + pgvector 表结构（chunk_embeddings）
2. 双写 Chroma + pgvector，后台对比两边 top-k 一致
3. exact 搜索先做正确性基线，再按需开 HNSW
4. shadow 一周无差异后灰度切换，Chroma 保留只读回滚

**验收**：DB 与向量 membership 数量 100% 一致；scope 过滤无越界；pgvector Recall 相对 exact ≥95%；可一键回滚。

---

### 单元 S：解析器 bake-off（多引擎选型）

**为什么**：现在只用 MinerU 一个引擎，没有用数据证明它是不是最优。PP-Structure、Docling 各有所长，用同一批水利文档同条件对比，选出「在你的文档上得分最高且成本可接受」的引擎。

**内容**：
1. 建 20–30 份代表文档评测集（扫描规范、旋转页、复杂表格）
2. 三个引擎（PP-StructureV3 / Docling / MinerU）同硬件、同 dpi 跑对比
3. 输出报告：字符准确率、条款号准确率、表格 TEDS、旋转纠正率、耗时/内存
4. 形成「按文档类型路由」表，而不是强迫一个引擎全包

**验收**：同一评测集上各引擎报告可复现；最终路由表有数据依据。

---

### 单元 T：P3 增强能力（质量稳定后按价值立项）

**为什么**：这些是「加分项」，不是「地基」。每项启动前必须说清它改善哪个已测指标，不能因为「更 AI」就做。

**内容**（按业务价值排序，逐个立项，不一次全做）：
1. 结构化表格问答（下载带来源的结果）
2. 文档版本对比与规范变更提醒
3. 多文档对比与冲突证据
4. 人工审核队列

6. 知识图谱 / 成本面板 / LangGraph-Agent（排在最后，视前面稳定程度再议）

## 三、依赖关系与建议顺序

```
单元 O（评测校准）──→ 铺路，先做
        ↓
单元 P（召回完整性）── 检索质量收尾，依赖 O 的尺子
单元 R（存储 pgvector）── 独立，可并行
        ↓
单元 S（bake-off 选型）── 决定引擎，应先于或并行于 Q
单元 Q（解析完整性）── 依赖 S 的结论（用哪个引擎做旋转/表格）
        ↓
单元 T（P3 增强）── 全部稳定后再碰
```

**建议顺序**：O → P → R → S → Q → T。
（R 与 P 可互换；S 与 Q 建议 S 在前，因为 bake-off 结论决定 Q 用什么引擎。）
