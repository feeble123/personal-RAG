## 一、为什么做（大白话）

现在系统只有两类人：

- **管理员 admin**：能管一切（管知识库 + 管账号 + 看审计）
- **普通用户 user**：只能提问

50 人上线后，问题来了：你不可能让每个能「上传文档、管知识库」的人都同时能「增删账号、把别人提成管理员」。需要一个**中间角色**：

| 角色 | 能干什么 | 关键边界 |
|---|---|---|
| **超管 superadmin** | 管知识库 + **管账号**（增删用户/改角色/重置密码）+ 看审计 | 唯一能管「人」的角色 |
| **库管 admin** | 管知识库（上传/重解析/删文档）+ 看审计 | **不能管账号**——防止库管把自己提成超管 |
| **普通 user** | 只提问/检索 | 不能进任何管理页 |

一句话：**管「内容」的和管「人」的分开**。库管能维护知识库，但没资格决定谁能当管理员。

## 二、权限矩阵（需你评审确认）

| 功能 | 超管 | 库管 | 普通 |
|---|---|---|---|
| 提问 / 检索 / 回答 | ✅ | ✅ | ✅ |
| 知识库管理（建库/删库/上传/重解析/删文档） | ✅ | ✅ | ❌ |
| 记忆库管理 | ✅ | ✅ | ❌ |
| 系统统计 | ✅ | ✅ | ❌ |
| 审计日志查看 | ✅ | ✅ | ❌ |
| **账号管理**（增删用户/改角色/重置密码） | ✅ | ❌ | ❌ |

> 唯一区别在最后一行：只有超管能管账号。其余管理功能，库管和超管都能做。

---

## 三、存量数据迁移（关键，保证老管理员不丢权）

现在系统里 `role="admin"` 的老管理员账号，迁移后**全部自动升级为 superadmin**：

```
UPDATE users SET role='superadmin' WHERE role='admin'
```

这样现有部署**无感升级**——老管理员照常能管一切，只是多了一个「库管」新角色可用。

## 四、改动清单（分 3 个单元）

### 单元 1：后端角色模型 + 依赖 + 迁移

- `deps.py`：
  - 新增 `require_superadmin`（`role != "superadmin"` 拒绝）
  - `require_admin` 改为「admin **或** superadmin 都算管理员」（知识库/记忆库/审计两个角色都能进）
- `db/models.py`：`User.role` 注释更新为 `superadmin / admin / user`
- `main.py`：首次启动种子账号 `role="superadmin"`
- alembic 数据迁移：存量 `admin` → `superadmin`

**验收**：新库种子账号是 superadmin；存量 admin 升级后 `GET /auth/me` 返回 superadmin。

### 单元 2：后端接口权限收紧 + 角色校验

- `users/routes.py`（账号管理）：
  - 所有接口 `AdminUser` → `SuperAdminUser`（只有超管能管账号）
  - 创建/改角色的校验从 `("admin","user")` 改为 `("superadmin","admin","user")`
- 审计日志接口 `GET /admin/audit-logs`：保持 `AdminUser`（库管也能看）
- 系统统计接口：保持 `AdminUser`
- 记忆库管理接口：保持 `AdminUser`（现状就是 AdminUser，不动）

**验收**：库管访问账号管理接口 → 403；超管正常；库管访问知识库管理 → 正常。

### 单元 3：前端三级角色适配

- `types.ts` / `client.ts` / `App.tsx`：role 类型加 `'superadmin'`
- `router/index.tsx`：`RequireAdmin` 改为 `role === 'admin' || role === 'superadmin'`；新增 `RequireSuperAdmin`（仅 superadmin）
- `App.tsx`：用户管理路由改用 `RequireSuperAdmin`；知识库/记忆库/审计保持 `RequireAdmin`
- `UserManager.tsx`：角色下拉三级；「设为管理员/普通」按钮支持三级切换
- `UserMenu.tsx`：账号管理入口仅 superadmin 显示；知识库/记忆库/审计 admin+superadmin 显示
- `Login.tsx`：登录跳转逻辑（admin 和 superadmin 都跳知识库管理）

**验收**：三级角色创建/切换正常；普通用户看不到账号管理入口；库管看不到账号管理入口但能看到知识库管理。
