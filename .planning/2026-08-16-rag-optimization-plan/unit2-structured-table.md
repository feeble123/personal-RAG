> 制定日期：2026-09-04
> 决策：一步到位，但只做**一套「看懂表格列」的通用能力**，Excel 与 MinerU PDF 表格**共用**。
> 数据模型：**方案 A**（Chunk 表加 `table_data` JSON 字段）。
> 状态：**待用户确认后逐单元执行**

---

## 〇、先对齐：这到底在优化什么（大白话）

现在表格进库后是一行行扁平文本，系统**不知道「哪列是列名、哪列是值」**。所以：

- 问「列出所有方案名」→ 只能向量猜，会漏、会串列
- 问「动力配电箱有几台」→ 数值靠猜
- 问「9 月之后完成的方案」→ 日期散在每行里，筛不准

**目标**：让系统「看懂表格的列」，这类问题走精确结构化查询，不再猜。

**关键澄清**：MinerU 只能读 PDF，读不了 Excel。所以「以后都走 MinerU」对 PDF 成立，对 Excel 不成立——Excel 必须走自己的解析器。但这**不费劲**：Excel 天生是表格，pandas 读进来已经是「列名+一行行数据」，所谓「补结构」就是「别把现成结构拍扁、直接存下来」，十几行顺手事。真正难的是 MinerU 读 PDF 表格的「多行表头」，留到最后单独处理。

---

## 一、已查实的技术事实

| 事实 | 结论 |
|---|---|
| MinerU PDF 表格 `element.table` | ✅ 已有 `{rows, header_path}`（含①填的合并单元格） |
| Excel `element.table` | ❌ 是 `None`，要补（但 pandas 结构现成，很便宜） |
| Excel 切片粒度 | 42 元素 → parent-child 合并成 8 块（多行一块） |
| Chunk 表字段 | 没有存表格结构的字段 |
| 查询链路 | 无结构化查询分支 |
| 意图识别 | 无表格查询识别 |
| 评测靶子 | gold_data.py 已有 `table` 题：「动力配电箱的数量是多少？」（期望 `3`） |

---

## 二、数据模型（方案 A，已确认）

`Chunk` 表加一个可空 JSON 字段 `table_data`：

```json
{
  "table_id": "doc10-制度体系",       // 标记「同一张表」，跨块聚合用
  "columns": ["序号", "方案名称", "完成时间"],
  "rows": [["1", "质量保证体系", "2025-09-15"]],
  "row_index": 0
}
```

表格仍是普通 chunk（照常进向量/BM25 检索），只是多带一份结构化数据。非表格块 `table_data = NULL`。

## 三、单元切分（精简版：5 个单元，逐个验收）

### 单元 2-1｜解析层：表格结构就绪
**做什么**：Excel parser 补 `element.table`（顺手，pandas 现成结构直接存，十几行）；MinerU 已就绪，确认即可。
**验收**：单测——Excel 与 MinerU 两种解析器都产出 `{columns, rows}` 结构，列名与源文件一致。

### 单元 2-2｜管道打通：结构穿透切片 + 落库
**做什么**：`ParentChildChunk` 加 `table_data`（`table_id` + 本块覆盖的行）；`Chunk` 加 `table_data` JSON 字段 + Alembic 迁移；`_write_chunks` 写入。
**验收**：单测——48 行表格切 N 块、按 `table_id` 拼回完整 48 行；落库后 `table_data` 正确、非表格块为 NULL、迁移 roundtrip 通过。

### 单元 2-3｜查询：结构化读表服务
**做什么**：按 `table_id` 聚合 → 按列取值 / 按列筛选 / 计数。
**验收**：用真实 doc10/doc11 验证——「列出所有方案名」逐条一致；「动力配电箱有几台」= `3`；「9 月之后完成」命中与源文件一致。

### 单元 2-4｜接入：识别表格问题走精确通道
**做什么**：意图识别「表格结构化查询」，命中走 2-3 精确通道；不命中照旧走向量检索（零回归）。
**验收**：评测集 `table` 题 Recall 达标；`enumeration` 题（台账列表）走结构化不漏；全量评测无退化。

### 单元 2-5｜尾巴：MinerU PDF 表格多行表头
**做什么**：多行表头 → 规范列名合成；合并单元格已由①填好。
**验收**：PDF 表格结构化可查；「切成条」表格页不漏列；全量评测无退化。

## 四、验收总标准（数字）

- 按列取值：方案名逐条一致、不漏、不串列
- 数值列：「动力配电箱有几台」= `3`（精确）
- 日期筛选：「9 月之后」命中行 = 源文件按日期过滤结果
- 无回归：现有检索/评测不退化；pytest 全量绿

## 五、风险与边界

- 多行表头是版式难点（2-5 单独处理，不阻塞 2-1~2-4 主线）
- 结构化查询是「精确辅助通道」，检索主链路不动
- 只做水利领域；碰真实数据（PG/Chroma）先备份/先 dry-run
