## 1. 系统长什么样（三句话看懂）

1. **前端**（浏览器界面）：`frontend/`，React 18 + AntD 5 + Vite
2. **后端**（真正干活的服务）：`backend/app/`，FastAPI 异步服务
3. **知识层**（数据存哪儿）：
   - **PostgreSQL**：知识库、文档、切片原文、用户、对话、记忆……（关系数据）
   - **Chroma 向量库**（`backend/data/.chroma`）：每段文字的"语义指纹"，用来找**意思相近**的段落
   - **BM25 索引**（内存，启动时从数据库重建）：按**关键词**找段落，和向量互补

外部业务系统还能通过 `/api/v1/*` 直接调用（见第 4 章），这是和平台对接的主入口。

### 2.6.1 MCP 服务（agent 的第二种接入方式）

REST 之外，本体能力同时以 **MCP（Model Context Protocol）** 暴露，支持 MCP 的 agent 可直接挂载：

```bash
cd backend
.venv\Scripts\python.exe -m app.mcp          # stdio 传输
```

| 工具 | 作用 | 与 REST 的对应 |
|---|---|---|
| `ontology_search` | 词 → 实体（本体实例 / 图节点） | `GET /v1/ontology/search` |
| `ontology_entity` | 实体详情 + 1~2 跳邻居 + 证据 | `GET /v1/ontology/entities/{uid}` |
| `ontology_neighbors` | 纯子图（节点 + 边） | `GET /v1/ontology/neighbors/{uid}` |
| `get_parameter_priors` | 参数推荐卡（范围/初值/依据） | `GET /v1/ontology/params` |
| `ontology_ask` | 事实包，本体不够自动回退向量检索 | `POST /v1/ontology/ask` |

- 代码：`app/mcp/{__init__,server,__main__}.py`；业务逻辑全在 `services/graph/ontology/queries.py`（REST 与 MCP **共用同一份**，不会漂移）。
- 返回约定：成功 `{"ok": true, ...}`；可预期失败 `{"ok": false, "error": {"code", "message"}}`（如 `GRAPH_DISABLED`），agent 可分支处理。
- 硬约定：**stdout 只走协议帧**，日志一律走 stderr；`python -m app.mcp` 不跑 FastAPI lifespan，自己开会话。
- 联调脚本：`E:\GPT-Codex\tools\mcp_stdio_smoke.py`（官方客户端真实握手 + 调 3 个工具）。

## 3. 入库流水线（文档怎么变成能检索的切片）

一个文档从上传到可检索，走 5 步。每一步失败都会保留旧版本（不会把已有知识弄坏）。

| 步 | 阶段名 | 干什么 | 代码文件 |
|---|---|---|---|
| 0 | `queued` | 上传后进队（同一文档不会重复投递） | `app/modules/ingestion/manager.py` |
| 1 | `parsing` | 识别格式 → 选解析器（PDF 文字层/OCR/MinerU、Word、Excel、MD）→ 输出统一结构 | `app/services/parser/factory.py`、`router.py`、`pdf.py`、`ocr.py`、`mineru.py`、`docx_parser.py`、`excel_parser.py`、`text_parser.py`、`ir.py` |
| 2 | 分块 | 按章节/标题边界切段（不跨章节），父子块保留上下文 | `app/services/chunker.py`、`app/services/chunking/parent_child.py` |
| 3 | `embedding` | 每段文字算"语义指纹"（BGE-M3，带缓存不重复算） | `app/services/embedding.py`、`embedding_cache` 表 |
| 4 | `indexing` | 写入 Chroma 向量库 + 重建 BM25 关键词索引 | `app/services/vector_store.py`、`app/services/bm25.py` |
| 5 | `publishing` | 原子切换：新版本生效、旧版本退役 | `app/modules/ingestion/manager.py`、`document_versions` 表 |

## 4. 对外接口契约（平台对接看这一章）

### 4.1 鉴权

- 请求头：`X-API-Key: <密钥>`
- 密钥来源：`backend/.env` 的 `EXTERNAL_API_KEY`（**留空 = 接口关闭，返回 503**）
- 不复用用户登录令牌（JWT）；服务间调用专用
- 生成方式：`python -c "import secrets;print(secrets.token_urlsafe(48))"`

### 4.2 `POST /api/v1/search` —— 只要原文片段和出处

请求：

```json
{ "query": "明渠均匀流的形成条件", "top_k": 5, "kb_id": 12, "doc_ids": null }
```

### 4.4 错误码与限流

统一响应体：`{"code": "错误码", "message": "人话说明"}`

| HTTP | code | 场景 |
|---|---|---|
| 401 | `UNAUTHORIZED` | 没带 / 带错 `X-API-Key` |
| 422 | — | 参数校验失败（如空问题、`top_k` 越界） |
| 429 | — | 触发限流 |
| 502 | `GENERATION_FAILED` | 大模型调用失败（对方挂了/欠费/网络） |
| 503 | `EXTERNAL_API_DISABLED` | 服务端没配 `EXTERNAL_API_KEY` |

限流（按 IP，可在 `.env` 调）：检索 `EXTERNAL_RATE_LIMIT=120/minute`，问答 `EXTERNAL_CHAT_RATE_LIMIT=20/minute`。

### 4.5 对接时务必知道的三件事

1. **问答接口不写用户会话**：外部调用没有用户身份，不会污染网页端的聊天记录（有测试守着）。
2. **问答要花钱**：每次调用真实大模型，按 token 计费；`top_k` 越大越贵。检索接口不调模型，免费。
3. **非流式**：一次返回完整答案，通常 10~40 秒，调用方超时要设 ≥ 120 秒。

### 4.6 本体接口（`/api/v1/ontology/*`，给自动建模 agent）

同一把 `X-API-Key`；限流 `EXTERNAL_RATE_LIMIT`（默认 120/分钟）。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/types` | 本体里有哪些实体/关系/属性（agent 用来规划调用） |
| GET | `/params?name=sm&climate=湿润` | 参数推荐卡：条件收窄、冲突并列、**无依据不出数** |
| GET | `/search?q=` | 实体链接：问题里的词 → 本体实例 / 图节点 |
| GET | `/entities/{uid}?depth=1` | 实体详情 + 邻居 + 证据 |
| GET | `/neighbors/{uid}?depth=1` | 纯图查询（图库未启用返回 503） |
| POST | `/ask` | 本体优先问答，返回**事实包**；本体事实不够时回退向量检索并标 `fallback_used=true` |

`POST /ask` 的返回（节选）：

```json
{
  "question": "湿润地区 sm 怎么取",
  "facts": [
    {"kind": "parameter_prior", "subject": "sm", "range": [5.0, 50.0],
     "range_level": "general", "evidence_level": "traceable", "source": "ontology"}
  ],
  "evidence": [{"doc_name": "新安江模型手册.pdf", "page": 4, "chunk_id": 28192}],
  "fallback_used": false,
  "sources": ["ontology"],
  "latency_ms": 12
}
```

`facts[].kind` 有三种：`parameter_prior`（本体参数卡）、`graph_node`/`graph_edge`（图谱事实）、`text_chunk`（回退的向量检索片段）。调用方按 `source` 区分可信度。

## 6. 数据表地图（PostgreSQL）

| 表 | 存什么 | 关键点 |
|---|---|---|
| `users` | 账号、密码哈希、角色 | 密码永不明文 |

| `knowledge_bases` | 知识库（名称、文档数、切片数、状态、**业务域**） | 删除知识库会级联；`business_domain` 见 `app/core/taxonomy.py` |
| `documents` | 文档（文件名、类型、状态、当前版本） | `active_version_id` 指向生效版本 |
| `document_versions` | 每次解析的版本 | 重灌失败时旧版本仍可用 |
| `chunks` | 切片原文 + 元数据（章节/页码/条款/表格数据） | **检索的最小单位** |
| `ingestion_jobs` | 入库任务（阶段/重试/进度/错误） | 进度条与任务监控来源 |
| `index_versions` | 索引版本 | 发布时原子切换 |
| `citations` | 回答引用的快照 | 文档改了旧回答也不会指错 |
| `embedding_cache` | 文本指纹缓存 | 同样的文字不重复花钱算 |
| `semantic_cache` | 相似问题的答案缓存 | 启动/重灌时清空，防旧答案劫持 |
| `qa_memory` | 问答记忆库（好评沉淀） | 检索时可被优先召回 |
| `audit_logs` | 管理员操作审计 | 谁在什么时候改了什么 |
| `graph_sync_runs` | 图谱同步/导入运行记录 | 跑没跑成功、抽了多少、哪些行被拒 |
| `graph_edge_evidence` | 每条图事实的原文证据 | 答案里每条结论都能点回原文；人工台账 `chunk_id` 为空 |
| `graph_entity_aliases` | 实体别名表 | 查询侧「问题里的词 → 图节点」的权威来源；`kb_id=0` 表示全局实体 |
| `ontology_instances` | 本体实例（参数先验等人工知识） | **真相源**：人工改过的值只存这里，Neo4j 只是可重建的索引；`(profile_id, entity_type, name, kb_id)` 唯一。当前有 13 个参数实例（profile=`tuning`，取值来自通用手册，待专家复核） |
